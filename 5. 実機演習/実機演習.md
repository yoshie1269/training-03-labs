# フロー
# ステップ1：物理結線（ケーブル配線）
構成図の通りにLANケーブルを接続します。
※お持ちの「ハブ」は、設定用の作業PCから各ネットワーク機器の管理ポートへ接続するための「管理用ネットワーク」として活用すると、コンソールケーブルを都度差し替える手間が省けて便利です。

Client から 左のL2スイッチ へ接続。

左のL2スイッチ から 2台のL3スイッチ へそれぞれ接続。

2台のL3スイッチ から 右のL2スイッチ へそれぞれ接続。

右のL2スイッチ から ESXiサーバ の物理NIC2つ（例: vmnic0, vmnic1）へ接続。

# ステップ2：L2スイッチの設定（VLANの構成）
L2スイッチは、各ネットワークを論理的に分割し、L3スイッチへ橋渡しする役割を持ちます。（※以下はCisco機器を想定した設定の流れです）

左のL2スイッチ（クライアント側）

VLAN 10を作成します。

クライアントが繋がるポート、および両方のL3スイッチに繋がるポートを アクセスポート として設定し、VLAN 10を割り当てます。

右のL2スイッチ（サーバ側）

VLAN 20を作成します。

ESXiサーバが繋がる2つのポート、および両方のL3スイッチに繋がるポートを アクセスポート として設定し、VLAN 20を割り当てます。

# ステップ3：L3スイッチの設定（HSRPによる冗長化）
L3スイッチでVLAN間ルーティングを有効にし、HSRPを設定してゲートウェイを冗長化します。

L3スイッチ1（メイン機として設定）

ip routing コマンドでルーティング機能を有効化します。

VLAN 10インターフェース設定:

IPアドレスを設定 (192.168.10.252)。

HSRPの設定: 仮想IP (192.168.10.254) を設定し、Priorityを高く（例: 110）してActive（メイン）にします。

VLAN 20インターフェース設定:

IPアドレスを設定 (192.168.20.252)。

HSRPの設定: 仮想IP (192.168.20.254) を設定し、Priorityを高くしてActiveにします。

L3スイッチ2（スタンバイ機として設定）

同じく ip routing を有効化します。

VLAN 10インターフェース設定:

IPアドレスを設定 (192.168.10.253)。

HSRPの設定: 仮想IPは同じ (192.168.10.254) を指定し、Priorityはデフォルト（100）のままにしてStandby（待機）にします。

VLAN 20インターフェース設定:

IPアドレスを設定 (192.168.20.253)。

HSRPの設定: 仮想IP (192.168.20.254) を指定し、Standbyにします。

# ステップ4：ESXiサーバのネットワーク設定（NICチーミング）
ケーブルやL2スイッチの障害に備え、ESXi側でネットワークの冗長化を行います。

vSphere Client（またはHost Client）でESXiにログインします。

「ネットワーク」>「仮想スイッチ (vSwitch0)」のプロパティを開きます。

アップリンクの追加: 物理NIC（vmnic0 と vmnic1）の両方をvSwitchのアップリンクとして割り当てます。

NICチーミングの設定: チーミングのポリシーを確認します。デフォルトの「ルートベースの送信元仮想ポートID」等で、両方のアダプタが「アクティブ」になっている状態であればチーミングは完了しています。

# ステップ5：仮想マシンの作成とApacheの構築
普段Linux環境に触れられているのであれば、ここはスムーズに進むはずです。

ESXi上に仮想マシンを作成し、任意のOS（AlmaLinuxやUbuntuなど）をインストールします。

ネットワーク設定: OSのIPアドレスを固定（192.168.20.10）、デフォルトゲートウェイをHSRPの仮想IP（192.168.20.254）に設定します。

Apacheの構築:

パッケージマネージャ（dnfやapt）でApache（httpd または apache2）をインストールします。

サービスを起動し、自動起動を有効化します。

ファイアウォール（firewalld等）でHTTP (80番ポート) の通信を許可します。

テスト用に簡単な index.html を作成しておくと確認がしやすいです。

# ステップ6：クライアントの設定と疎通確認
クライアントPCから最終的な接続確認を行います。

クライアントPCのIPアドレスを 192.168.10.10、デフォルトゲートウェイを 192.168.10.254 に設定します。

コマンドプロンプトやターミナルを開き、サーバ（192.168.20.10）へ ping が通るか確認します。

ブラウザを開き、http://192.168.20.10 にアクセスしてApacheのテストページが表示されれば構築完了です！

# ステップ7：障害テスト（冗長性の検証）
ここがこのミッションの醍醐味です。構築したものが本当に「壊れない（止まらない）」かを検証します。

クライアントからサーバへ継続的にPingを打ち続けます。（Windowsなら ping 192.168.20.10 -t、Mac/Linuxなら ping 192.168.20.10）。

テスト1（HSRPの検証）: ActiveになっているL3スイッチ1の電源を抜く、またはケーブルを抜きます。数回のPingタイムアウトの後、L3スイッチ2が処理を引き継ぎ、Pingの応答が復活することを確認します。

テスト2（NICチーミングの検証）: ESXiに繋がっている2本のLANケーブルのうち、1本を抜きます。Pingが途切れることなく通信が継続できれば成功です。

各ステップで状態確認コマンド（L3スイッチでの show standby など）を叩きながら進めると、プロトコルの動きがより深く理解できるはずです。応援しています！

# ステップ0：Tera Termでの接続準備
PCとL2スイッチの「Console」ポートを、コンソールケーブル（水色の平たいケーブルなど）で繋ぎます。

Tera Termを起動し、「新しい接続」画面で「シリアル(R)」を選択します。

ポート(P)のプルダウンから、ケーブルが認識されているCOMポート（例：COM3など）を選び、「OK」を押します。

# L2スイッチ設定

## ステップ1：特権モードとグローバルコンフィギュレーションモードへの移行
設定を変更するための権限レベルを上げます。
```bash
Switch> enable
Switch# configure terminal
Switch(config)#
```

## ステップ2：ホスト名（機器名）の変更（任意ですが推奨）
どちらのスイッチを触っているか分からなくなるのを防ぐため、名前を付けます。
```bash
Switch(config)# hostname L2-SW-Left
L2-SW-Left(config)#
```

## ステップ3：VLANの作成
スイッチ内部に「VLAN 10」という論理的なグループを作成します。
```bash
L2-SW-Left(config)# vlan 10
L2-SW-Left(config-vlan)# name Client-NW  ←（分かりやすい名前を付けます）
L2-SW-Left(config-vlan)# exit
L2-SW-Left(config)#
```

## ステップ4：ポートへのVLAN割り当て（アクセスポート設定）
物理ポート（ここでは例として GigabitEthernet 0/1 ～ 0/3）をVLAN 10に所属させます。これで、これらのポートに繋いだ機器はVLAN 10のネットワークに参加します。
```bash
L2-SW-Left(config)# interface range fastEthernet 0/1 - 3
L2-SW-Left(config-if-range)# switchport mode access
L2-SW-Left(config-if-range)# switchport access vlan 10
L2-SW-Left(config-if-range)# exit
L2-SW-Left(config)#
```

## ステップ5：L2スイッチへのIPアドレス割り当て（管理用IP）
ここでご質問の「IPの割り振り」を行います。先ほど作成したVLAN 10の仮想インターフェースに入り、IPアドレスを設定します。
※ここではクライアント（.10）やHSRP（.254）と被らないよう、192.168.10.11 をスイッチのIPとして割り当てます。
```bash
L2-SW-Left(config)# interface vlan 10
L2-SW-Left(config-if)# ip address 192.168.10.20 255.255.255.0
L2-SW-Left(config-if)# no shutdown  ←（インターフェースを起動します）
L2-SW-Left(config-if)# exit
L2-SW-Left(config)#
```

## ステップ6：デフォルトゲートウェイの設定
このスイッチ自身が、別のネットワーク（例えばVLAN 20のサーバ）と通信するために、出入り口（HSRPの仮想IP）を教えてあげます。
```bash
L2-SW-Left(config)# ip default-gateway 192.168.20.20
```

## ステップ7：設定の保存（重要）
機器を再起動しても設定が消えないように保存します。
```bash
L2-SW-Left(config)# end
L2-SW-Left# write memory
Building configuration...
[OK]
L2-SW-Left#
```

# 確認
設定が完了したら、show vlan brief や show ip interface brief といった確認コマンドを打つと、設定した内容が一覧で表示されて正しく割り当てられているか確認できます。

# L3スイッチ

## ステップ1：基本設定（ルーティングの有効化とVLAN作成）
まず、スイッチが「ルーター」として動くように設定し、必要なVLANを定義します。これは両方のL3スイッチで行います。
```bash
Switch(config)# hostname L3-SW-1  （2台目は L3-SW-2）
L3-SW-1(config)# ip routing  ←（重要：これでL3として動作します）
L3-SW-1(config)# vlan 10
L3-SW-1(config-vlan)# name Client-VLAN
L3-SW-1(config)# vlan 20
L3-SW-1(config-vlan)# name Server-VLAN
L3-SW-1(config-vlan)# exit
```

## ステップ2：物理ポートの設定（L2スイッチとの接続）
L2スイッチから繋がっているポート（例：GigabitEthernet 0/1, 0/2）をそれぞれのVLANに割り当てます。
```bash
L3-SW-1(config)# interface fastEthernet 0/1
L3-SW-1(config-if)# switchport mode access
L3-SW-1(config-if)# switchport access vlan 10
L3-SW-1(config-if)# exit

L3-SW-1(config)# interface fastEthernet 0/2
L3-SW-1(config-if)# switchport mode access
L3-SW-1(config-if)# switchport access vlan 20
L3-SW-1(config-if)# exit
```

## ステップ3：HSRPの設定（クライアント側 VLAN 10）
ここからが冗長化の本番です。SVI（VLANインターフェース）に物理IPを設定し、さらにHSRPの仮想IPを設定します。

L3-SW-1（メイン側）の設定
```bash
L3-SW-1(config)# interface vlan 10
L3-SW-1(config-if)# ip address 192.168.10.100 255.255.255.0  ←（自身のIP）
L3-SW-1(config-if)# standby 10 ip 192.168.10.254              ←（仮想IP：これがゲートウェイになる）
L3-SW-1(config-if)# standby 10 priority 101                  ←（値を高くしてメインにする）
L3-SW-1(config-if)# standby 10 preempt                       ←（復旧時に自動でメインに戻る設定）
L3-SW-1(config-if)# stanby 10 track fastEthernet 0/2 10
L3-SW-1(config-if)# no shutdown
```

L3-SW-2（待機側）の設定
```bash
L3-SW-2(config)# interface vlan 10
L3-SW-2(config-if)# ip address 192.168.10.200 255.255.255.0  ←（自身のIP）
L3-SW-2(config-if)# standby 10 ip 192.168.10.254              ←（仮想IPは共通）
L3-SW-1(config-if)# standby 10 priority 100
L3-SW-2(config-if)# standby 10 preempt
L3-SW-2(config-if)# no shutdown
```

## ステップ4：HSRPの設定（サーバ側 VLAN 20）
同様にサーバ側のゲートウェイも冗長化します。

L3-SW-1（メイン側）の設定
```bash
L3-SW-1(config)# interface vlan 20
L3-SW-1(config-if)# ip address 192.168.20.100 255.255.255.0
L3-SW-1(config-if)# standby 20 ip 192.168.20.254
L3-SW-1(config-if)# standby 20 priority 101
L3-SW-1(config-if)# standby 20 preempt
L3-SW-1(config-if)# stanby 20 track fastEthernet 0/1 10
L3-SW-1(config-if)# no shutdown
```
L3-SW-2（待機側）の設定
```bash
L3-SW-2(config)# interface vlan 20
L3-SW-2(config-if)# ip address 192.168.20.200 255.255.255.0
L3-SW-2(config-if)# standby 20 ip 192.168.20.254
L3-SW-1(config-if)# standby 20 priority 100
L3-SW-2(config-if)# standby 20 preempt
L3-SW-2(config-if)# no shutdown
```

## ステップ5：状態の確認
設定が終わったら、Tera Termで以下のコマンドを打ち、正しくメイン（Active）と待機（Standby）が分かれているか確認します。
```bash
L3-SW-1# show standby brief
```
出力結果の「State」列を確認してください。
L3-SW-1側で Active と表示されている
L3-SW-2側で Standby と表示されている
Virtual IP が 192.168.x.20 になっている

これが確認できれば、片方のスイッチが故障しても、もう片方が瞬時に 192.168.x.254 の役割を引き継ぐ準備が整ったことになります。最後に両方のスイッチで write memory を実行して設定を保存するのを忘れないようにしてください。
→PriorityのL3スイッチを停止し、StandbyのL3スイッチがアクティブになったことを確認


# ESXiのネットワーク冗長化
ESXiのネットワーク冗長化（NICチーミング）ですね。L2スイッチやL3スイッチが黒い画面（CUI）でのコマンド操作だったのに対し、ここはWebブラウザを使ったグラフィカルな画面（GUI）での操作になります。

## ステップ1：ESXi Host Client へのログイン
まずはESXiの管理画面にアクセスします。

作業用PCのWebブラウザ（ChromeやEdgeなど）を開きます。

アドレスバーに、ESXiの管理用IPアドレスを入力してアクセスします。（例：https://192.168.10.xx）

ログイン画面が表示されたら、ユーザー名（通常は root）とパスワードを入力してログインします。

ポート0が管理者権限のため、チーミングは別のNICを使うこと。

## ステップ2：仮想スイッチ（vSwitch）の設定画面を開く
ESXi内部の仮想的なスイッチに、物理的なLANケーブル（物理NIC）を紐づけていきます。

画面左側のナビゲーションペイン（メニュー）から、[ネットワーク] をクリックします。

右側の画面で [仮想スイッチ] タブをクリックします。

一覧に表示されている vSwitch0（デフォルトで作成されている仮想スイッチ）をクリックします。

## ステップ3：アップリンク（物理NIC）の追加
標準状態では、インストール時に使用した1つ目の物理NIC（vmnic0）だけが繋がっている状態なので、ここに2つ目の物理NIC（vmnic1）を追加します。

1. 構成の考え方
管理用（現在）: vmnic0 (または3) → PC直結

服用（チーミング用）: vmnic1 と vmnic2 → 右のL2スイッチへ接続

この場合、既存の vSwitch0 をいじるのではなく、新しく仮想スイッチ（vSwitch1）を作るのが最も安全で分かりやすいです。

2. 手順：新しいvSwitchでチーミングを作成する
新しい仮想スイッチの作成

左メニュー [ネットワーク] ＞ [仮想スイッチ] タブ ＞ [標準仮想スイッチの追加] をクリック。

vSwitch名: vSwitch1

アップリンク1: vmnic1 を選択。

[追加] をクリック。

2つ目のNIC（vmnic2）を追加

作成した vSwitch1 をクリックし、[設定の編集] を開きます。

[アップリンクの追加] を押し、vmnic2 を選択します。

これで、このスイッチに2本の足がつきました。


## ステップ4：NICチーミングポリシーの確認・設定
追加した2本の物理NICを「どういうルールで冗長化させるか」を設定します。

同じ「vSwitch1 の編集」ウィンドウ内で、[NIC チーミング] という項目を展開（クリックして開く）します。

以下の設定になっているか確認、または変更します。

ロード バランシング: ルートベースの送信元仮想ポート ID （デフォルトのままでOKです。仮想マシンごとに通信する経路を分散させます）

ネットワーク フェイルオーバーの検出: リンク状態のみ （ケーブル抜けや対向スイッチのダウンを検知します）

スイッチへの通知: はい

フェイルバック: はい

少し下にスクロールし、「フェイルオーバーの順序」を確認します。

アクティブなアップリンク の下に、vmnic1 と vmnic2 の両方が配置されていることを確認します。（もし「スタンバイ」や「未使用」に入っていたら、「アクティブ」へ移動させます）

設定が完了したら、ウィンドウ右下の [保存] をクリックします。

3. ポートグループの作成（仮想マシン用）
スイッチを作っただけでは仮想マシンは通信できません。「出口」となるポートグループを作ります。

左メニュー [ネットワーク] ＞ [ポートグループ] タブをクリック。

[ポートグループの追加] をクリック。

名前: Server-Network（任意）

VLAN ID: 0 (L2スイッチ側でアクセスポート設定にしているなら0でOK)

仮想スイッチ: 先ほど作った vSwitch1 を選択。

[追加] をクリック。


## ステップ5：トポロジ（構成図）での最終確認
設定が正しく反映されたか、視覚的に確認します。

vSwitch1 の詳細画面に戻ります。

画面中央の「トポロジ」という図を確認します。

仮想スイッチ（vSwitch1）の右側に、物理アダプタとして2つのアイコン（vmnic1 と vmnic2）が緑色の状態で接続されている図になっていれば成功です。

これで、ESXiから右のL2スイッチに向かう経路が2本束ねられ、どちらか1本のケーブルが断線したり、接続先のポートが壊れたりしても、もう1本の経路を使って通信が継続できるようになりました。
