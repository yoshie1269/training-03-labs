
# Webサーバ移行手順（sorryページ → SSL発行 → 本番切替）

本手順では以下を実施する。

- 移行中の **sorryページ表示**
- 新ドメインの **SSL証明書発行**
- AP / DB移行完了後の **本番切替**

---

# 00 事前準備

## 0-1 古いドメインの確認

### この工程でしていること

既存環境で使用していたドメインを確認する。  
SSL証明書発行時に旧ドメインを指定する場合があるため  
事前に確認しておく。

---

## 0-2 セキュリティグループ設定

### この工程でしていること

移行作業中に外部からアクセスできるよう  
Webサーバのセキュリティグループを一時的に開放する。



### 対象セキュリティグループ

CL_TEAME_SG_WEB



### インバウンドルール

|タイプ|ポート|送信元|
|---|---|---|
HTTP|80|0.0.0.0/0|


### 注意

移行完了後は  
必要なアクセス範囲へ戻す。

---

# 01 移行開始（sorryページ表示）

## 1-1 sorryページ表示

### この工程でしていること

移行作業中に  ユーザーへメンテナンス画面を表示する。

APサーバへアクセスさせないよう  nginx側で **sorryページを表示**させる。


### web1を実行
```bash
~/Desktop/sorry-switch.sh 172.31.0.233
```


### web2を実行
```bash
~/Desktop/sorry-switch.sh 172.31.1.179
```


### 確認

ブラウザでアクセス
```bash
www.teame.entrycl.net
```


### OKの状態

メンテナンス中ですしばらくお待ちくださいの **sorryページが表示される**

---

# 02 SSL証明書発行

## 2-1 ServerName変更 + 証明書発行

### この工程でしていること

- nginxのServerNameを新ドメインへ変更
- Let's EncryptでSSL証明書発行



### 実行コマンド
```bash
~/Desktop/certbot.sh 172.31.0.233 www.teame.entrycl.net <古いドメイン>
```


### 引数の意味

|引数|意味|
|---|---|
172.31.0.233|WebサーバIP|
www.teame.entrycl.net|新ドメイン|
\<古いドメイン>|旧環境ドメイン|


### 処理内容（スクリプト内部）

- nginx ServerName変更
- certbot実行
- SSL証明書発行
- nginx設定更新



### 成功確認

以下が表示されれば成功

`証明書発行処理が正常終了しました。`

---

# 03 AP / DB移行

### この工程でしていること

以下の移行作業を実施する。

- Application Server 移行
- Database 移行
- データ同期
- 動作確認

---

### 注意

この間は **sorryページ表示状態**

- サービス停止をユーザーへ明示
- SSL証明書の安全な発行
- AP / DB移行中の誤アクセス防止
- スムーズな本番切替
